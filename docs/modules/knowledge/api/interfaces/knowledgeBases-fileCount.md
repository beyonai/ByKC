# knowledgeBases-fileCount

## 功能描述

同步返回指定知识库下所有目录层级中的未删除文件数量，不统计目录。文件是否完成构建不影响计数；有效知识库没有文件时返回 `0`。

## 接口信息

| 项目 | 值 |
| --- | --- |
| 方法 | `POST` |
| 路径 | `/api/v1/knowledgeBases/fileCount` |

## 请求 Header

| Header | 必填 | 值 | 说明 |
| --- | --- | --- | --- |
| `Content-Type` | 是 | `application/json` | 请求体类型 |
| `Accept` | 否 | `application/json` | 期望的成功响应类型 |

> 服务本身未定义额外的业务认证 Header；如由网关统一认证，按部署环境要求携带。

请求体：`application/json`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `knCode` | string | 是 | 知识库编码 |

## 请求示例

```json
{
  "knCode": "123"
}
```

## 成功响应示例

HTTP 状态码：`200`。

```json
{
  "resultCode": "0",
  "resultMsg": "success",
  "resultObject": {
    "fileCount": 12
  }
}
```

有效知识库没有文件或只有目录时，成功响应中的 `fileCount` 为 `0`。

## 响应参数

| 字段路径 | 类型 | 必返 | 说明 |
| --- | --- | --- | --- |
| `resultCode` | string | 是 | 业务结果码；`0` 表示成功，`-1` 表示失败 |
| `resultMsg` | string | 是 | 业务结果说明 |
| `resultObject` | object | 是 | 成功时为文件数量统计结果；失败时为空对象 |
| `resultObject.fileCount` | integer | 成功时是 | 指定知识库下所有层级的未删除文件总数，值大于等于 `0` |

## 失败响应示例

知识库不存在或已删除时，HTTP 状态码为 `422`，不返回文件数量。

```json
{
  "resultCode": "-1",
  "resultMsg": "knowledge base not found: 123",
  "resultObject": {}
}
```

缺少必填参数或参数校验失败时，HTTP 状态码同样为 `422`，响应沿用[通用失败信封](../common.md#失败响应)。实际 `resultMsg` 说明失败原因，请勿只根据文案分支处理。

本接口保留实际 HTTP 错误状态码：参数无效或知识库不存在为 `422`，依赖未配置为 `503`，未预期异常为 `500`；错误响应中的 `resultObject` 为空对象。

## 特殊逻辑

- 统计范围为指定知识库整体，包含根目录及任意深度子目录下的文件。
- 仅统计未删除的文件条目；目录和已逻辑删除的文件不计入数量。
- 未构建、构建中、构建成功及构建失败的文件均计入数量。
- 同一文件的内容更新历史、构建任务及切片不单独计数；文件更新、改名或在同一知识库内移动不增加文件数量。
- 仅接收知识库标识，不提供目录路径、构建状态筛选或分页参数。
- 有效空库与不存在或已删除的知识库严格区分：前者成功返回 `0`，后者返回错误。

## 路径与定位规则

- `knCode` 是知识库编码，HTTP 请求中使用字符串。
- 根据 `knCode` 定位知识库，不接收文件或目录路径。
