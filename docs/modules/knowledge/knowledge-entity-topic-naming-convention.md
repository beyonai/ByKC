# Knowledge Entity / Topic 命名规范

## 1. 目标与边界

本规范用于在语义候选、Entity/Topic 角色和 Topic owner 已确定后，从原文支持的多个合法表面名中稳定选择一个规范名。

命名决策不得改变：

- 候选是否输出；
- 候选是 Entity 还是 Topic；
- Topic 的 owner；
- Entity/Topic 的语义边界。

禁止用正则、关键词表、子串包含或文档特例进行语义改名。确定性代码只校验非空、原文连续出现、完全等值去重和引用有效性。

## 2. 共同原则

1. **原文可回溯**：规范名必须在模型所见原文中连续出现。
2. **一个语义一个主名**：不用多个表面名重复输出同一对象或方向。
3. **最小充分名**：名称应尽量简洁，但不得删除区分语义边界所必需的限定词或后缀。
4. **不用容器替代方向**：“概述、核心功能、其他、总结”类文档组织名不得取代已明确展开的稳定语义方向。
5. **命名顺序固定**：每次面对同一原文候选集，都必须按本规范的优先级选名。

规范、指南、手册、模板或目录类文档需先完成对象边界判断：若标题命名一个可维护的文档型知识对象，且正文持续以“本规范/本指南/本手册”定义它，应区分该对象与它所适用的平台、渠道或产品。这是命名前的身份判断，不是根据后缀自动建实体。

## 3. Entity 命名

### 3.1 主名优先级

从高到低依次为：

1. 文中明确声明的官方名或全称；
2. 标题、正文与总结稳定使用的专名；
3. 文中最精确、无歧义的同指名。

主名保留官方大小写、数字、版本标识以及有辨识度的名称部分。已有精确名称时，不得选择宽泛类别、修辞昵称、关系短语或自创组合名。

### 3.2 Alias

- 全称、简称、缩写、曾用名只有在原文明确同指时才是 alias。
- 多个可独立检索的同指名应分别保留，不用连接它们的整串文字代替独立 alias。
- 选定主名后回查全文，逐类检查全称、简称、缩写和旧称；主名正确不代表 alias 完整。
- 若原文用“A/B”或“A、B”并列多个同指名，每个名称分别输出为 alias；此时每个 alias 元素只包含一个名称，不保留连接后的整串。
- 上下位词、相关词、子功能、关键词、产品类别和描述短语不是 alias。
- alias 语义由 LLM 判断，不得在确定性层按括号、斜杠、连字符或子串自动拆分。

## 4. Topic 命名

### 4.1 先定方向，后选名

Topic 命名不能用于“猜” Topic。必须先确认它是绑定 owner、有稳定边界且具有持续检索价值的方向，再收集同一方向的原文名称候选。

### 4.2 名称优先级

从高到低依次为：

1. 标题或导语/摘要明确声明的全文信息任务与中心方向名；
2. 在主体正文、多个主要部分或总结中稳定使用的明确方向标签；
3. 只出现在单个局部章节、附录、例子或影响分析中的名称。

先按上述中心性分级，只在同级内比较最小充分名；低级候选不得压过合法的高级候选。中心性同级时，优先保留文档研究范围的最具体稳定限定，不用更宽的上位名替代标题或导语已指定的中心方向。

章节标题只是名称来源之一，不能自动证明 Topic 应该存在。

### 4.3 最小充分名

- 保留识别方向所需的限定词。
- 保留“规范、系统、架构、方案、机制、工程”等能区分语义角色的后缀。
- 当前数量、版本、营销性形容或局部实现限定不用于区分同一 owner 下的并列方向时，若基础名在原文连续出现且仍唯一无歧义，选基础名。
- 若“主名：解释性副标题”中的主名已能唯一表示方向，选主名；否则保留完整连续名。
- 若“主名（等价译名）”有明确主名，选文档主要语言下的主名。
- 若作者明确以“A / B”作为一个固定标签，且未指定主名，保留该完整连续标签。
- 中英组合名不临时翻译或拼接；目录、主要章节标题或定义句已给出固定连续写法时，同等中心性下优先该写法；只有稳定单语名时保留单语名。
- Topic 不输出 aliases；其他原文表述保留在 evidence 中。

## 5. 证据与评测

- 每个 Entity/Topic 的至少一个 evidenceRef 应支持所选名称与它的语义边界。
- Gold 中的每个可接受名称都必须在对应原文中连续出现。
- Gold 可以用同一 `names` 组表示经独立人工裁决后确认的等价规范名，不得使用模糊匹配、子串或正则表达式。
- 对同一文档独立运行至少两次，Entity 与 Topic 分别使用规范名集合的最小 Jaccard 验收稳定性。

## 6. 变更规则

- 一轮只处理一个主要错误类别。
- 命名规范改动先在 development 语料上双跑，再运行冻结 regression。
- 不得修改 regression/holdout 金标来迎合当前模型输出。
- 任何已暴露答案的 holdout 不再用作最终未见验收集。
- 只读质量门禁通过前不得运行持久化 Discovery。
